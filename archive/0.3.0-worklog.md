# Docking, direct positioning, and mutable ship events

## review

The previous implementation already separated simulation from rendering and
scheduled from event time correctly. Two gaps mattered here: render-only
exponential easing cut voyage corners, and ship generations identified recycled
render slots but did not invalidate queued simulation events.

## changes

- Default to GLM-inspired dock slots, unloading/loading delays, and cargo retries
  when no good has six units. Preserve instant turnaround as a reset option.
- Render exact linear voyage positions by default; optional trailing smoothing.
  Add optional active dashed routes and GLM stock bars/notched ship shapes.
- Select a ship on the canvas and reroute it or sink it through ship options.
  Reroutes retain cargo and start at the current world position. Sinking discards
  cargo and does not request a replacement.
- Add a parallel revision array to the heap, including growth and both sift
  directions. Validate ship events before processing; stale entries are drained
  without simulation effects. Revisions survive ship slot reuse. Timeline hides
  stale entries while queue size intentionally includes them.
- Update invariant checks to allow a current loading/unloading event instead of
  requiring an arrival while docked. Leave standalone prototypes untouched.

## validation

- queue_check, sim_events_check, sim_jump_check, gui_smoke: pass.
- sim_updates_check: heap revision growth/sifting, reroute position continuity,
  stale arrival rejection, sinking, slot reuse, cargo waiting/retry, and instant
  mode pass.
- sim_measure: 20,000 minutes, 162,528 events, 1,233,429 delivered, stock fill
  53.2%, queue peak 36. Docked ships are excluded from travel-time assertions.
- git diff --check: clean. GUI validation uses the existing headless DOM/canvas
  smoke test, not an interactive browser visual inspection.
