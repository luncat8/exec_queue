# 0.1.0 — worklog

## steps

1. Queue: parallel typed arrays + binary heap, `drainUntil` calls the handler
   after popping so handlers can schedule follow-ups. Tests cover ordering,
   capacity growth and the draft scenario (delivery at 10, loaders at 11/12).
2. Simulation: ships, ports, cargo, dispatch/arrival events. First run exposed
   an argument-order bug (`arrive(time, ship)` was called as `(time, ref)`) —
   caught by the "arrival in the past" invariant in `sim_measure`.
3. Dispatch flood: every dispatch pushed another dispatch, and at the fleet cap
   they rescheduled forever, so the queue grew to 2326 entries. Removed the
   branching push, seeded 30 dispatch events instead, and retry a replacement
   request only while the fleet is full.
4. Fleet decay: retirement replacements were dropped at the cap, leaving 1–18
   ships. Fixed by retrying the request in 10–50 minutes and scheduling the
   replacement 5–20 minutes after retirement. Fleet now holds 26–30.
5. Production was applied before draining a jump, so every event in the batch
   saw end-of-window stocks. Moved it into `produce(time - t)` in the handler;
   `sim_jump_check` now proves 1-minute and 37-minute stepping match exactly.
6. GUI: canvas, supply bars, ship easing, HUD, pause/step mode/slider/reset,
   port clicks. Headless stub-DOM test runs the frame loop and controls.
   Ship slots are reused after retirement, so the renderer keys easing on a
   per-slot generation counter; otherwise a recycled slot sails across the map.
7. A click on a port while all 30 slots are busy is deferred like a retirement
   replacement instead of vanishing; `sim_events_check` proves it is served
   (26 minutes in the seed-5 run) and that every living ship holds exactly one
   queued arrival.

## validation

- `queue_check` ok.
- `queue_bench`, 50k events: heap 12.6 ms, sorted array 167.9 ms (13.4x).
- `sim_jump_check`: identical state, 16,964 events, 26 ships.
- `sim_measure`, 20,000 min, seed 11: 56,658 events (2.83/min, ~1.3M/s cpu),
  26 ships alive, 1,375,771 delivered, queue 30, stock min 0.2 / avg 99.5 / max
  120 (82.9% fill, 26.3% of bins below 75%, no sustained empty ports).
- `sim_events_check`: invariants hold over 3,000 minutes; deferred click served.
- `gui_smoke`: frames, jump mode, click, pause, resize, reset all run clean.
- Canvas output rendered offscreen with `@napi-rs/canvas` (scratch install, not
  committed) at 1280x800 @1x/@2x and 390x844: ships, bars, flash ring and the
  high-DPI transform all draw correctly.

## next

Add a third event type — per-port consumption ticks — so supplies are a real
sink instead of overflowing at `STOCK_MAX`, and the supply bars oscillate at all
speeds. A queue histogram in the HUD would also make the jump behaviour visible
without reading the event counter.
